# Data Contracts

Field-level semantics for every canonical contract. JSON Schema exports are
generated by `python scripts/export_schemas.py` into `schemas/`.

## Canonical instrument identity

```
{EXCHANGE}_{SEGMENT}|{LOCAL_ID}

NSE_EQ|RELIANCE                       cash equity (symbol)
NSE_EQ|INE002A01018                   cash equity keyed by ISIN (Upstox style)
BSE_EQ|500325                         BSE scrip code
NSE_FO|BANKNIFTY-2026-09-24-CE-52000  option contract
NSE_IDX|NIFTY 50                      index
```

Rules:
- `EXCHANGE ∈ {NSE, BSE}`, `SEGMENT ∈ {EQ, SME, FO, MF, DEBT, IDX, CURRENCY, COMMODITY}`.
- The pipe form is the storage/lineage id. NautilusTrader receives
  `{SYMBOL}.{VENUE}` (e.g. `RELIANCE.NSE`, `...52000.NSEFO`) via the mapping layer.
- ISINs are validated (12 chars, alpha prefix) wherever present.
- Options require expiry + strike + CE/PE + underlying or construction fails.

## InstrumentIdentity

| Field | Type | Notes |
|---|---|---|
| instrument_id | str | canonical, primary key everywhere |
| exchange / segment | enum | |
| symbol | str | local exchange symbol |
| isin | str? | validated |
| security_type | enum | EQUITY, INDEX, ETF, SGB, FUTURE, OPTION, ... |
| currency | str | default INR |
| lot_size / tick_size | int / float | feed Nautilus precision/increment |
| expiry/strike/option_type/underlying | — | mandatory for options |

## MarketBar

One OHLCV row for exactly one canonical instrument and timeframe.

| Field | Notes |
|---|---|
| timestamp | bar open/close time, timezone-aware UTC after normalization |
| timeframe | `1m…1M`; stored as string in parquet |
| open/high/low/close | validated: high ≥ max(o,c), low ≤ min(o,c), all > 0 |
| volume | ≥ 0; float (shares) |
| open_interest | derivatives only |
| source | NSE / BSE / UPSTOX / MANUAL |
| source_timestamp | what the vendor claimed |
| ingestion_timestamp | when we received it |
| raw_hash | sha256 of the exact raw payload this row came from |
| adjustment_status | UNADJUSTED → FULLY_ADJUSTED by the adjustment engine |
| quality_status | RAW → VALIDATED / SUSPECT / REJECTED |

**Never** a generic `{"value": ...}` dict. Unknown upstream keys go to `extra`
or are dropped loudly — never silently mapped onto price fields.

## CorporateAction

Separate table/dataset from prices. Key fields:

| Field | Notes |
|---|---|
| action_type | DIVIDEND, BONUS, SPLIT, RIGHTS, MERGER, DEMERGER, BUYBACK |
| announcement_date / record_date / ex_date / effective_date | all optional but ex_date drives adjustment |
| ratio / old_value / new_value / amount | DIVIDEND requires amount; SPLIT/BONUS require ratio or old+new |
| raw_payload_hash | lineage back to the raw record |

Adjustment semantics (`adjustment_ratio()`): the multiplicative factor applied
to **pre-ex-date** bars. 10→2 split ⇒ ×0.2. Bonus 1:1 ⇒ ×0.5. Dividends are
recorded, not applied, by default — total-return treatment is an explicit
research decision.

## Announcement

Never mixed with price data. `announcement_id`, `instrument_id`,
`published_at` (UTC), `category`, `headline`, `document_url`, plus full
lineage. This is the event-study input.

## OptionInstrument / OptionQuote

Options are first-class instruments. Greeks (delta/gamma/theta/vega) and IV
live **only** on `OptionQuote`, never on equity records. Bid ≤ ask enforced.

## Lineage

Every persisted answer to "where did this number come from?":

```
source, source_tool, source_request_id, source_timestamp,
ingestion_timestamp, raw_hash, schema_version
```

Reproducibility rule: same dataset hash + config hash must reproduce any
recorded experiment result. If it doesn't, it isn't production quality.

## Storage layout

```
data/
├── raw/{nse,bse,upstox}/{tool}/{YYYY-MM-DD}/{sha256}.json   (+ .meta.json)
├── normalized/bars_{tf}/{EXCHANGE}/{LOCAL_ID}.parquet
├── validated/bars_{tf}/{EXCHANGE}/{LOCAL_ID}.parquet
├── catalog/            Nautilus ParquetDataCatalog
├── research.duckdb     views over normalized_*/validated_* parquet
└── metadata.db         instruments, jobs, runs, quality_reports
```

Parquet for data, DuckDB for research SQL, metadata DB for operations only.
